The earlier viewer (morph, overlays, why card, timeline) is in studio/web/js/*.js: reuse it, do not rewrite it.

THE VISUALS ARE THE MOST IMPORTANT PART OF THE WHOLE DEMO. Make this striking, smooth and projector-readable. 3Dmol.js (already vendored, pinned).

Build
1. `api.js`: single client; ALWAYS use relative URLs (`/api/...`) because a gateway proxies them; helpers for SSE (with auto-reconnect and `Last-Event-ID`-free replay), JSON, and a health probe. If the health probe fails, show a clear banner "Backend offline: showing a recorded replay" and load `studio/web/replay/index.json` -> run files (the integrator will add recordings; support the format = the saved list of `Event`s).
2. `stages.js` + the `#stage-switcher` nav: a 3-step stepper (1 Binding -> 2 Pose -> 3 Pharmacology) plus a "Manual" toggle (mount for the other UI agent: just expose `window.MetisStages.onStageChange(cb)` and show/hide `#panel-manual`). Target picker (`GET /api/targets`), known-drug picker, "Run" button per stage, status chips that say predicted / precomputed / replay.
3. `pocket.js`: render the target protein (`GET /api/data/structures/<id>.pdb`) as a soft cartoon with a translucent pocket surface around `pocket_residues` and residue labels on hover; camera auto-frames the pocket. Keep the ligand view from the existing viewer working inside this scene (a single 3Dmol viewer with protein model + ligand model, ligand drawn in sticks with the existing glow/halo overlays).
4. `pose.js`: Stage 2: request `POST /api/poses`, poll `GET /api/poses/{id}`, show a progress animation, then play: the ligand glides from outside the pocket into the predicted pose and the protein morphs from the apo structure (`apo_pdb`) to the predicted protein (`protein_pdb`) with a toggle for the overlay (apo ghosted, predicted solid) and residue displacement highlighting; show pose confidence and DynamicBind affinity next to the PLAPT value with a plain-language note that both are predictions.
5. Stage 1 view: stream `POST /api/runs {stage:"binding", target_id, seed_smiles}`; reuse the existing candidate/morph playback; a live chart of best predicted affinity per generation (small SVG, no library) and a table of the top 5 leads with Tanimoto-to-seed and affinity, plus a button "Dock this lead" (stage 2) and "Optimise pharmacology" (stage 3, sending `seed_molblock` = the pose ligand converted to a mol block when a pose exists).
6. Stage 3 view = the existing studio inside the pocket scene; add a compact "binding stays" badge fed by `score.extras.plapt_affinity` when present.
7. Polish: consistent dark theme, loading skeletons, keyboard shortcuts documented, no console errors, works at 1280x720 and a phone width. Provide screenshots (headless browser or the in-app browser) against mock/stub data in your handoff.

Until the real endpoints land, develop against small fixtures you create in `studio/web/fixtures/` (a target JSON, a PDB, a pose result) served with `?fixtures=1`.
Acceptance: all three stages and the stepper work end to end on fixtures; no console errors; screenshots attached. Do not edit the files owned by the other UI agent (`studio/web/js/manual/`, `studio/web/js/panels/`).
