Context: the Space `Adithya-Rao/Metis-Space` is currently a Gradio-SDK Space with hardware ZeroGPU, no app file, and a persistent storage bucket mounted at `/metis-data`. Keep the Gradio SDK (the owner wants no Docker). Goal: the public URL `https://adithya-rao-metis-space.hf.space` serves the studio UI and proxies the API to a Lambda backend.

Build
1. `deploy/space/README.md` with the Space YAML header (`sdk: gradio`, `app_file: app.py`, keep the existing title/emoji/license fields except fix the licence to `mit` only if the repo licence allows it: check the repo's LICENSE; otherwise leave it and say so), `deploy/space/requirements.txt` (fastapi, uvicorn, httpx, gradio at the version the Space expects; keep it minimal, no rdkit/torch).

The `BACKEND_URL` can be read at request time from the persistent bucket file `/metis-data/backend_url.txt` if present, overriding the variable, so a rotating tunnel URL needs no restart.
3. Local test harness: run your gateway locally against a fake backend (a tiny FastAPI that streams SSE) and against `studio.server.app` in mock mode, and show that SSE streams through the proxy with correct ordering, that backend-down falls back cleanly, and that the key is never leaked to the browser. Include tests.
4. ZeroGPU question: find out (documentation / source of the `spaces` package / Space settings docs) whether a ZeroGPU Space can start with no `@spaces.GPU` function, and write down the safe fallback (switch hardware to cpu-basic, no SDK change). Do not change Space settings yourself.
