# Task: binding (branch demo/binding). Owns studio/binding/ (new).

Objective: the stage-1 fitness: predicted binding via PLAPT, packaged as a `Scorer` the existing engine can use, with guards against the GA gaming it.

Build
1. `studio/binding/plapt_backend.py`: wrap the repo's PLAPT (`binding_module/binding_affinity/plapt.py`, read-only import; it loads Rostlab/prot_bert and seyonec/ChemBERTa-zinc-base-v1 from the official Hub, and an ONNX head in the repo). Batch API `predict(sequence, smiles_list) -> list[pKd or the model's affinity unit; record which]`, device auto (CUDA if present, else CPU), a persistent cache (diskcache) keyed by (sequence hash, canonical SMILES), the protein embedding computed ONCE per sequence. Cache dir from env `STUDIO_CACHE_DIR` (default `./.cache/studio`). An injectable `FakeBackend` (deterministic, clearly named) for tests and offline dev.
2. `studio/binding/scorer.py`: `BindingScorer` implements the `Scorer` Protocol. `score(smiles, config)` returns a `ScoreResult` whose descriptors come from `studio.scoring.RDKitScorer` and whose `extras` has `plapt_affinity`; `composite` = desirability of binding (monotone, relative to the SEED drug's score so improvements show up) times guard factors: Tanimoto (Morgan r2) to the seed >= `config.min_similarity_to_seed` (hard floor), MW <= `config.max_mw` (default seed MW + 120), sanity checks (use `studio.sanity.checks.check_child` if the module exists on your branch, else a small local fallback marked as such), no new structural alerts. The target comes from `config.target_id` via `studio.data.loader.get_target` (may not exist yet; develop against a stub JSON in your tests).
3. Stage-1 wiring helper `studio/binding/stage.py`: `build_binding_engine(...)` that reuses `studio.wiring.build_engine` pieces with the BindingScorer and forces `policy_guidance=0` semantics (pure GA).
4. Gaming check script `python -m studio.binding.gaming_check --target <id>`: (a) known drugs vs 200 random drug-like decoys: do known drugs score higher? (report AUROC or rank), (b) run the GA for 10 generations from a known drug and report the best child's affinity, its Tanimoto to the seed, MW, alerts, and whether the improvement looks like a size effect (correlation of affinity with heavy-atom count across the run). Report honestly, including if PLAPT is uninformative on a target.
5. Tests with FakeBackend: guards enforced, cache hit, seed-relative desirability monotone.

Acceptance: tests green offline; if the real PLAPT runs on this machine (CPU is fine for a handful of molecules, models download from the Hub) report seconds per molecule cold/warm; otherwise state that the real run is deferred to the Lambda agent and give the exact command.
